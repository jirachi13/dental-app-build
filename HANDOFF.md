## Sprint 120 (input values, not just presence) - DONE 2026-09-04, tsc + build clean, **19/19 rule tests + 8/8 browser**. Closes backlog #51.
Sprint 62 made the REQUIRED fields undriftable by deriving asterisks and enforcement from one list. This does the same for VALUES.

- **New `src/app/utils/studentValidation.ts` - ONE source**, used by the Add Student form, the CSV/XLSX bulk import, and the student-info edit on the chart. OCR inherits it free, since OCR fills the same form. Duplicating "what counts as a valid birthday" across form and importer is exactly how `demoStudents.ts` drifted.
- **Birthday is the one with teeth, and it is a REPORTING-CORRECTNESS fix, not form polish.** Age is derived at examination date (Sprint 57b), so a mistyped year silently moves a pupil into the wrong DOH age bracket and the report still looks authoritative. Rules: a real date, not future, age **3-25** (generous at the top on purpose - the target is a mistyped YEAR like 2020 -> 2002, not policing enrolment).
- **ALL CAPS IS ALLOWED - decided, not overlooked.** DOH paper forms are filled in caps, OCR reads caps, and the encoder is copying a form, so the record should match the paper on audit. Names accept letters (incl. n-tilde/accents), spaces, hyphen, apostrophe, period; digits are rejected. Cap is **60**, taken from `docs/DATA-MODEL.md` rather than invented.
- **PH phones by STRUCTURE, not a carrier list**: mobile `09XXXXXXXXX` / `+639XXXXXXXXX`, landline 9-10 digits incl. area code (covers NCR `(02) XXXX-XXXX`). Punctuation and `+63` are normalised first, so the encoder can type it the way the form prints it. **Must stay client-side or pre-encryption** - `contact_number`/`guardian_contact` are encrypted, so a DB constraint or regex query on the stored value is impossible (Sprint 26).
- **Native constraints alongside the JS checks** (CLAUDE.md prefers platform features): `min`/`max` on the date picker and `maxLength=60` on the name inputs, both derived from the SAME constants as the JS rules - measured live as `min=2001-09-03 max=2023-09-03`. A picker offering a date the save would reject is the same disagreement Sprint 62 removed.
- **⚠ MEASURED BEFORE ENABLING IT ON EDIT: only 1 of 27 existing records fails these rules** (a contact number). So the edit path was guarded too; the cost is that one legacy value must be corrected before that pupil can be edited, which is the point. **Had the number been large, this would have been entry-only.**
- **Deliberately NOT on the Mongoose model.** Every existing record predates these rules and CRUD updates run `findById + save()`, so a schema-level rule would make existing records unsaveable on their next edit - the same reasoning that kept `REQUIRED_STUDENT_FIELDS` off the model.
- **Verified:** 19/19 rule cases (ALL CAPS accepted, n-tilde accepted, `Dela Cruz-O'Brien` accepted, digits rejected, 60 ok / 61 rejected, future rejected, age 40 and age 1 rejected, `09171234567` / `0917-123-4567` / `+639171234567` / `(02) 8123-4567` accepted, too-short and letters rejected) plus **8/8 in a real browser** - picker bounded, cap live, caps preserved, a bad phone blocks the save and names the field, and nothing was written.
- **NOT DONE, recorded honestly: the SERVER does not enforce any of this.** All three paths are client-side. The offline queue replays POSTs straight to the API, so a row crafted around the UI still gets in. Server-side would mean either duplicating the rules in `server/` (the drift risk this sprint exists to avoid) or sharing a module across the `src/` / `server/` boundary, which the project has no precedent for. **Now backlog #52.**

- **⚠ `pkill -f` DOES NOT STOP THE DEV SERVERS ON THIS MACHINE — and it fails SILENTLY.** `npm run dev` and `npm run dev:server` both run as **`node`**, so `pkill -f "vite"` / `pkill -f "tsx watch"` match nothing, exit quietly, and leave the servers running. Found 2026-09-03: a session reported "dev servers stopped" when both were still up, and the proof arrived a sprint later as `EADDRINUSE :::4000` when a second API server could not bind.
  - **Stop them by PORT, from PowerShell:** `Get-NetTCPConnection -LocalPort 4000 -State Listen` → `Stop-Process -Id <OwningProcess> -Force`. Ports in play: **4000** (API), **5173** (Vite).
